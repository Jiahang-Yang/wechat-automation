# 发布：推草稿箱 + 同步列表

## 完整流程（必做 4 步，顺序不可乱，不可省略）

> ⚠️ **第 4 步「获取文章列表」是固定步骤**：每次推送草稿后必须执行（即使草稿未发布、列表无变化也要跑，用于确认与同步）。

1. **获取草稿箱** → `api_get_drafts.py`（看当前草稿，写 工具/草稿列表.json）
2. **推送草稿** → `api_push_draft.py 文章.wechat.html --cover 素材/封面.png`（推前自动判重，命中同名自动中止）
3. **复核草稿箱** → 再跑一次 `api_get_drafts.py`（确认新草稿已入箱）
4. **获取文章列表** → `browser_push.py` 无参（刷新 工具/文章列表.json，账本式合并）

> 第 1~3 步走 API（秒级完成）；第 4 步只能走浏览器（文章列表 API 个人号拿不到），无参自动无头、不弹窗、约 6~10 秒。

## 硬性要求：浏览器操作必须分步汇报（必读，任何场景都适用）

> **凡使用 Playwright 操作浏览器的步骤（`browser_push.py`，无论无参/带参、无论使用者还是助手场景），一律：**
> **后台任务运行 + 分 2~3 次读取中间进度 + 在对话里逐步转述给使用者，不得只给最终结果、不得用 grep/管道过滤掉中间输出。**

正确做法：
1. 先发进度消息（如「即将自动获取已发布文章列表（约 6~10 秒）…」）；
2. `run_in_background` 运行 `browser_push.py`（输出重定向到临时 log）；
3. 等 3 秒左右读一次 log，转述「第 1 步 启动完成（X 秒）→ 第 2 步 登录中」；再等几秒读一次，转述「第 2 步 登录完成 → 第 3 步 读取中」；
4. 完成后展示清单 + 总结。

## 两条路径怎么选

- **路径 A · API（默认）**：`工具/api/.env` 存在且 `api_get_drafts.py` 能拿到 token → 走 API。
- **路径 B · 浏览器备用**：`.env` 缺失 / AppSecret 错 / **IP 白名单拦截**（40164）/ 网络异常 → API 调不通 → 走浏览器（`browser_push.py` 带文章参数，查草稿→推送→获取列表一气呵成）。
- **API 报 40164（IP 不在白名单）时**：直接切路径 B 继续本次任务，**同时建议用户修复白名单**（按「白名单」技能：查 IP → 拼开发者平台链接（自动带 AppID）→ 给出链接 + IP 让用户添加）。恢复 API 不阻塞本次推送。

## 路径 A：API（4 步命令）

```bash
# 1. 获取草稿箱
../venv/Scripts/python.exe 工具/api/api_get_drafts.py
# 2. 推送草稿（推前自动判重；--force 可强制重推，--title 覆盖标题，--thumb 复用封面）
../venv/Scripts/python.exe 工具/api/api_push_draft.py 文章草稿/xxx.wechat.html --cover 素材/封面.png
# 3. 复核草稿箱
../venv/Scripts/python.exe 工具/api/api_get_drafts.py
# 4. 获取文章列表（无参自动无头，不弹窗）
../venv/Scripts/python.exe 工具/browser/browser_push.py
```

凭证：`工具/api/.env`（复制 `.env.example` 填 APPID/APPSECRET；IP 白名单留空即可任意 IP 调用）。
token 失效（40001）：`get_token(force=True)` 强制刷新即可（AppSecret 未变时）。

## 路径 B：浏览器备用

```bash
# 无参 → 仅获取文章列表；带文章 → 查草稿 → 推送 → 获取列表，一气呵成
./工具/browser/publish.sh xxx
#   可选：--force / --headless / --browser chromium|firefox；无参自动无头
```
- 登录态：`工具/browser/wechat_login.json`（首次需扫码，登录失效时脚本自动切带窗口弹窗等扫码）。
- 无参模式自动无头；若登录失效会自动切换带窗口模式弹窗（headless 弹不了扫码窗）。

## 文章列表同步（账本式合并）

- 本地 `工具/文章列表.json` 是**账本**，每次抓取是**近期快照**（首页只显示近期文章）。
- 合并规则：快照有新文章 → 追加末尾；快照标「已删除」→ 账本删除；账本有但快照没有（老文章被挤出首页）→ **保留**。
- 抓取已含：标题取 span（徽标不混入）、send_time 时间戳（划线链接）、tempkey 失效链接识别「已删除」。

## 面向使用者的输出规范（必读，执行时遵守）

使用者（父亲，非技术背景）让智能体执行时，**必须对话内分步汇报进度**（脚本已内置通俗文案，智能体负责转述节奏）：

1. **跑前**：发一条进度消息（如「即将自动获取已发布文章列表（约 6~10 秒）…」）。
2. **执行中**：后台任务运行 + 分 2~3 次读取中间进度并转述：
   - 第 1 步：正在启动…（启动完成，用时 X 秒）
   - 第 2 步：正在登录公众号后台…（登录正常 / 需扫码）
   - 第 3 步：正在读取已发布文章…（已读取到 X 篇）
3. **跑完**：展示文章清单（标题 + 日期）+ 总结（「本次已完成，总用时约 X 秒」）。
4. 技术细节（headless、token、进程回收耗时等）**不转述**，自己判断即可。
5. 登录失效时提示：「请在弹出的浏览器窗口中用微信扫码」。
6. API 路径（秒级）同样要报进度：① 查草稿箱 → ② 推送 → ③ 复核 → ④ 刷列表，每步一句。

## 关键约束（必读）

- **个人号无群发 API**：脚本只到**草稿箱**，**群发必须人工**在后台点（微信规定）。
- **防重复守卫**：两路径统一以「当前草稿箱」为准判重（API 走 `draft/batchget`；浏览器走后台 DOM 抓取，失败退读本地 草稿列表.json）。命中同名且未 `--force` 自动中止。`草稿记录.json` 已废弃。
- **登录态跨内核不通用**：微信把 UA 绑进登录态 cookie，Chromium↔Firefox 互不通用，单内核沿用即可。
- **保存必须 JS 派发**（仅浏览器路径）：对「保存为草稿」按钮派发 MouseEvent，坐标 click 会被浮层拦。
- **Dark Reader 卡死**：mp.weixin.qq.com 页面禁用该扩展，或改用微信 PC 版。
- Python 路径用 `D:/...` 不用 `/d/...`（Git Bash 传给 Python 的坑）。

## 迁移注意

- 换机器后首次跑浏览器路径需重新微信扫码（登录态不跨机器）。
- 浏览器内核固定 Chromium（`工具/setup.sh` 默认装）。
